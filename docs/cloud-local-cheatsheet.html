What each environment can reach, when to use which, and how to keep them in sync on a quant/trading project.

Why this matters for a trading project specifically

The scanner / order-placement code has to live local if it talks to a broker terminal (e.g. IBKR TWS/Gateway) that only runs on your desktop — a cloud session physically cannot reach it. Cloud sessions are fine for everything upstream and downstream of that: strategy logic, the dashboard UI, docs, tests against synthetic data.

Splitting work across both in one prompt

When a task has pieces for both environments, label them explicitly rather than burying the split in prose — a note like "this part is local" inside a paragraph is easy for a session to miss or misapply.

Do this:

CLOUD: build the FastAPI routes for trade approval and the React table that lists pending trades.

LOCAL: wire the "approve" button to place the actual order via the IBKR adapter, and test against the paper account.

Keeping the two in sync

  • Before checking "does X exist," run git fetch --all. Cloud and local can each be ahead of the other; a session that only looks at its own local branch state can miss work done in the other environment.
  • Keep a docs/latest-session-summary.md in the repo that every session overwrites (not appends) at the end of its work. The next session — in either environment — reads this first instead of you re-explaining state.
  • Use the Google Drive MCP connector for anything bigger than a session summary — running facts/decisions docs, longer-lived context you want both environments (and Project chat) to see without re-uploading. See the connector walkthrough below.

Quick decision checklist

  • Does this code need to talk to something only my machine can reach (broker terminal, local DB, hardware)? → Local
  • Is this UI, docs, scaffolding, or logic that doesn't touch anything local-only? → Cloud is fine and usually faster to spin up
  • Does the task span both? → Write two labeled prompts, CLOUD: and LOCAL:, in the same message
  • Starting a new session cold? → Have it fetch docs/latest-session-summary.md from the repo first
